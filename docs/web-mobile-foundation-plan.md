# Web / スマホ両対応の土台構想

## 1. 目的
現在の Expo ベース実装を活かしつつ、将来的に **Web とスマホ (iOS / Android)** の双方へ展開しやすい土台を整えることを目的とします。

この段階では「完全なWeb版の作り込み」ではなく、以下を重視します。
- 画面構造の共通化
- API接続の環境依存吸収
- レイアウトのレスポンシブ化
- 将来のWeb専用導線追加に耐えられる構成

---

## 2. 今回コード化した土台

### 2.1 共通ナビゲーション定義
画面タブ定義を `mobile/src/lib/navigation.ts` に切り出し、
アプリ全体で1つのナビゲーションメタデータを使う構成にします。

狙い:
- Web/スマホでナビゲーション定義を共通化
- 将来のサイドバー/ヘッダー切替に対応
- 画面追加時の変更箇所を減らす

### 2.2 レスポンシブ AppShell
`mobile/src/components/AppShell.tsx` を追加し、画面幅に応じて UI を切り替えます。

- **狭い幅**: 従来に近い下部タブ型
- **広い幅**: Web/タブレット向けのサイドバー型

狙い:
- 同じ screen 群を使いながら Web でも見やすい構成にする
- 将来のWeb専用メニューやダッシュボード導線を差し込みやすくする

### 2.3 画面コンテンツ幅の制御
`ScreenTemplate` で大画面時の `maxWidth` を制御し、
Webで横に広がりすぎない読みやすい画面幅へ統一します。

### 2.4 API Base URL の自動解決
`mobile/src/lib/api.ts` で API base URL を以下の優先順で解決します。
1. `EXPO_PUBLIC_API_BASE_URL`
2. Web実行時の `window.location.origin`
3. ローカル既定値 `http://localhost:3000`

狙い:
- スマホでは明示的な API URL を使える
- Webでは同一オリジン配信構成に自然対応できる

---

## 3. この構成で実現したいこと

### 3.1 短期
- Expo Web でも画面が破綻しにくい
- スマホとWebで共通ロジックを使える
- API接続先の切替がしやすい

### 3.2 中期
- Web専用の導線（例: 管理ダッシュボード）を追加しやすい
- スマホではタブUI、WebではサイドバーUIを維持しやすい
- shared hooks / shared components を増やしやすい

### 3.3 長期
- 認証導線、ルーティング、UIライブラリを整理して本格Web展開へ進める
- Expo継続か、Webだけ別フレームワークへ分離するかを判断できる
